# 仿真到实机

!!! danger "切换通信目标前停止运动程序"
    实机接入须有安全员和急停保障。不要让同一客户端同时发现仿真与实机中的同名服务。

## 过渡清单

- 确认 SDK、接口包和目标固件版本匹配。
- 确认模式查询、上身／全身调试、传感器和动作的实际端点名称。
- 确认关节顺序、限位、控制频率及 `kp` / `kd` 约定。
- 确认仿真和实机的动作资源、相机话题和网络配置。
- 停止旧客户端，切换 `ROS_DOMAIN_ID`，重新加载环境并核对发现结果。

SDK 包和环境脚本不需要切换版本；仿真与实机使用同一套客户端。配套程序存在的接口差异须在切换前明确。

## 验证步骤

1. 在仿真中完成模式查询和状态订阅。
2. 按运控规程验证低速行走、上身／全身调试及增益反馈。
3. 记录输入参数、接口包提交号、目标版本、反馈和故障结果。
4. 接入实机后重新从只读状态检查开始，不自动重放整套仿真控制指令。
5. 按[实机联调](../testing/real-robot.md)逐步执行。

```bash
ros2 run casbot2_py_tests get_state_test
ros2 run casbot2_tools interface_cli sub_motion_joint_state --seconds 5
```

## 已知差异

仿真可能锁定腿部或缺少动作资源；相机、雷达等话题依赖仿真是否模拟对应传感器。
物理接触、执行器限制和网络延迟也不能由接口一致推断为行为一致。

## RL / sim2sim

先按交付仿真包执行策略训练框架的 sim2sim 验证，检查关节映射、观测／动作维度、归一化、控制周期和限位。
具体训练与仿真命令由相应框架版本决定，本仓库没有提供该框架和 Binary。

确认策略后，按[二次开发手册](secondary-development.md)中强化学习部署一节放置 ONNX 文件、修改模型配置并重启配套运控程序。
路径以实际交付版本为准，部署前保留可回退的策略及配置；先仿真、再分步实机验证。
